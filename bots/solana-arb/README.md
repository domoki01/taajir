# روبوت تحكيم على سولانا (تعليمي)

روبوت يبحث عن فروق أسعار حقيقية بين البورصات اللامركزية على سولانا
(Orca، Raydium، Meteora…) عبر مجمّع التسعير Jupiter، وينفّذ صفقة
ذهاب-وإياب (USDC ← عملة ← USDC) عندما يتجاوز الربح المتوقع عتبة تغطي
الرسوم.

**هذا ليس آلة طباعة نقود.** القصص الفيروسية من نوع «0.90$ صارت 408
ألف» غير مثبتة. اقرأ قسم «ماذا رصدنا فعليًا» أدناه قبل أي شيء آخر.

## التشغيل

```bash
cd bots/solana-arb
npm install
cp .env.example .env
npm start
```

الوضع الافتراضي **DRY_RUN=true**: يرصد ويسجّل فقط، لا يلمس أي أموال ولا
يحتاج مفتاحًا خاصًا. اتركه أيامًا وراقب السجل قبل التفكير في المال الحقيقي.

للتنفيذ الحقيقي: ضع `DRY_RUN=false` مع `PRIVATE_KEY` (بترميز base58)
لمحفظة **مخصصة** فيها USDC للتداول وقليل من SOL للرسوم فقط.

## ماذا رصدنا فعليًا

تشغيل حقيقي على شبكة سولانا الرئيسية، حجم 10 USDC، سبع دورات:

```
cycle 1: SOL +2bps   JUP -5bps   JTO -26bps
cycle 2: SOL +7bps   JUP -6bps   JTO -22bps
cycle 3: SOL +3bps   JUP -1bps   JTO -15bps
cycle 4: SOL +0bps   JUP -2bps   JTO -22bps
cycle 7: SOL +0bps   JUP +0bps   JTO -17bps
```

أفضل فارق ظهر كان **+7 نقاط أساس** (0.07%)، أي نحو 0.007 دولار على صفقة
10 دولارات — قبل خصم رسوم صفقتين ورسوم الأولوية. والعتبة المطلوبة لتغطية
التكاليف 30 نقطة أساس. أي أن السوق كان **بعيدًا بأربعة أضعاف** عن مجرد
التعادل، ولم تُنفَّذ ولا صفقة واحدة. هذه هي الحالة الطبيعية: مجمّع مثل
Jupiter يوحّد الأسعار عبر البورصات، والفروق الباقية يلتقطها محترفون
بخوادم مخصصة وحزم Jito في أجزاء من الثانية، قبل أن يراها روبوت يعمل عبر
واجهة API عامة.

الأرقام السالبة على JTO ليست فرصة معكوسة، بل تكلفة الانزلاق والسيولة:
الدخول والخروج من العملة نفسها يخسر 0.2% لمجرد المرور.

## كيف يعمل

1. كل دورة يطلب من Jupiter تسعيرة USDC ← العملة، ثم تسعيرة عكسية
   بالكمية الناتجة.
2. إذا عاد المسار الدائري بأكثر مما بدأ به بفارق يتجاوز
   `MIN_PROFIT_BPS`، فهذه فرصة: تُسجَّل، وفي الوضع الحي تُنفَّذ الصفقتان.
3. كل دورة تطبع ملخّصًا بكل الفروق حتى السالبة منها، لأن «الفرص التي
   كادت» هي المعلومة المفيدة في وضع المحاكاة.
4. الطلبات تمرّ عبر منظّم معدل مع تراجع أسّي عند 429، لأن النقطة المجانية
   تحدّ بنحو طلب واحد في الثانية.

## المخاطر — اقرأها قبل وضع أي مال

- **التنفيذ غير ذرّي**: الصفقتان منفصلتان، وقد تختفي الفرصة بين الأولى
  والثانية فتُغلق الجولة بخسارة في حدود سماحية الانزلاق. هذا أكبر مصدر
  خسارة. التحكيم الذرّي يتطلب برنامج عقد خاص أو حزم Jito، وهو خارج نطاق
  هذه الأداة.
- **الرسوم**: كل جولة صفقتان، برسوم شبكة ورسوم أولوية. عتبة ربح أقل من
  الرسوم = خسارة مضمونة على المدى الطويل.
- **السيولة الوهمية**: فارق سعر كبير على عملة مغمورة يعني غالبًا سيولة
  لا تحتمل صفقتك، أو عملة احتيالية لا يمكن بيعها. المفاتيح الافتراضية
  هنا (SOL، JUP، JTO) سائلة عمدًا.
- **حدود الواجهات المجانية**: للجدية تحتاج RPC مدفوعًا ومفتاح Jupiter.
- **المفتاح الخاص**: لا يغادر جهازك، ولا يُضاف إلى git أبدًا
  (`.env` مستثنى). استعمل محفظة معزولة دائمًا.

## الإعدادات

كلها عبر متغيرات البيئة — انظر `.env.example` للشرح الكامل:
`RPC_URL`، `JUPITER_BASE_URL`، `JUPITER_API_KEY`، `REQUEST_INTERVAL_MS`،
`DRY_RUN`، `PRIVATE_KEY`، `TRADE_SIZE_USDC`، `MIN_PROFIT_BPS`،
`SLIPPAGE_BPS`، `SCAN_INTERVAL_MS`، `DEBUG`، `TOKENS`.

## البنية

| ملف               | الدور                                          |
| ----------------- | ---------------------------------------------- |
| `src/config.ts`   | قراءة الإعدادات والتحقق منها                   |
| `src/http.ts`     | منظّم المعدل وإعادة المحاولة مع التراجع الأسّي |
| `src/jupiter.ts`  | عميل تسعير وبناء معاملات Jupiter               |
| `src/scanner.ts`  | حساب الجولة الدائرية والفارق بنقاط الأساس      |
| `src/executor.ts` | توقيع وإرسال الصفقتين (الوضع الحي فقط)         |
| `src/index.ts`    | حلقة الفحص والتسجيل                            |
